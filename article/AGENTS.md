# AGENTS.md — kNN photo-z under sample shift

Каркас договора для работы над статьёй. Замените текст в угловых скобках своим.

## 0. Цель и образ результата

Вопрос исследования: как растёт ошибка kNN photo-z (k=10, feat1..feat5, обучение только на Happy A) при переходе от проверочной выборки B к C и D.

В конце работы в проекте существуют:
- `experiment/results/<файл результатов>` — числа, на которые опирается статья;
- `paper/paper.pdf` — статья на 2–4 страницы в шаблоне `ai4science_ysda`, обезличенная версия;
- записи в `diary.md` о каждом шаге и актуальный `STATUS.md`.

## 1. Критерий готовности

Агент вызывает проверки сам перед окончательным ответом. Работа принята, когда все команды
завершаются с кодом 0:

```
.venv/bin/python -m checks_hw2
.venv/bin/python article/checks/check_paper.py
```

## 2. Карта проекта

| Путь | Что лежит |
|---|---|
| `research/problem.md` | постановка: что дано, что требуется, когда результат верен, границы |
| `lit/lit.md` | источники с идентификаторами OpenAlex или DOI |
| `src/` | библиотека проекта: функции, которые вызывает эксперимент |
| `experiment/` | прогоны и `results/` |
| `paper/` | статья: `paper.tex`, класс шаблона, рисунки |
| `ONTOLOGY.yaml`, `GLOSSARY.md` | термины и обозначения |
| `WRITING.md` | правила текста |
| `STATUS.md`, `diary.md` | состояние работы и журнал |

Чего агент не знает сам:
- z безразмерно; определения σ_NMAD и выброса — из METHOD.md;
- данные в data/ только читать, не изменять;
- обозначения в статье берутся из `GLOSSARY.md`, термины — из `ONTOLOGY.yaml`.

## 3. Инструменты и границы

- Python из `.venv` (numpy, scipy, pandas, scikit-learn, PyYAML).
- Сборка статьи: `cd article/paper && tectonic -X compile paper.tex` (pdflatex нет).
- Сеть и Lean не нужны.

## 5. Протокол и режим работы

Порядок работы над кодом: требование, затем тест, затем реализация. Функции живут в `src/`,
код эксперимента их импортирует.

Порядок работы над статьёй: постановка → обзор источников → метод → проверка → эксперимент →
ограничения → воспроизводимость → заключение. Раздел об ограничениях пишется до раздела
с результатами. Текст — по `WRITING.md`. Каждый фрагмент статьи помечается `[порождено]`,
`[написано]` или `[источник]`.

## 6. Память и состояние

- `STATUS.md` — где работа сейчас и что дальше; читается в начале сессии, обновляется в конце.
- `diary.md` — одна запись на шаг: запрос, что сделано, чем проверено, итог проверки.
